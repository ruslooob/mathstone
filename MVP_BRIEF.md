# Концепция обучения и наград для MVP

Цель приложения — научить пользователя решать математические задачи на практике. Первый пример охватывает определители матриц 2×2 и 3×3.

Пользователь открывает части общей шпаргалки по мере обучения. Предполагается, что закрытые части будут мотивировать решать следующие задачи.

## Пользователь и исходные знания

Первый и пока единственный пользователь — владелец приложения. Он определяет, какие знания считать известными для каждого урока.

## Термины

Рабочие определения находятся в [GLOSSARY.md](GLOSSARY.md). Они служат временной основой обсуждения и требуют дальнейшего согласования. Сейчас используем название **шпаргалка**.

Названия и связи будущих разделов, направлений, уровней и модулей пока не определены.

## Объяснение и проверка

В текущий MVP входят задачи, для которых приложение может однозначно проверить ответ. Задания на доказательство и проверка доказательств отложены на следующие версии.

Объяснение показывает порядок вычисления и поясняет действия выбранной схемы. Полное доказательство в текущем MVP не требуется.

Содержание MVP ограничено двумя уроками по вычислению определителей 2×2 и 3×3. Существующие примеры и схемы служат основой объяснения. Геометрический смысл через площади и объёмы в текущий объём не входит.

## Задачи для практики

Приложение генерирует новые матрицы для практики. Пример в объяснении остаётся постоянным.

Новые задачи должны сохранять одинаковую сложность. Числа и результаты должны быть удобными для ручного счёта, как в учебниках.

Точные ограничения генератора отложены. Пользователь уточнит их на конкретных примерах, если возникнет проблема.

## Принятый порядок обучения

Пользователь свободно выбирает урок 2×2 или 3×3. Проходить их по очереди не требуется. Части общей шпаргалки открываются независимо, по мере решения задач на соответствующий приём.

Просмотр объяснения необязателен. Пользователь может сразу перейти к задачам и вернуться к объяснению в любой момент. Последовательность ниже описывает рекомендуемый учебный путь.

1. Пользователь смотрит видео, которое показывает способ решения на примере.
2. Пользователь получает задачу и решает её самостоятельно.
3. До получения награды пользователь может повторно смотреть видео.
4. Приложение проверяет ответ.
5. После пяти правильно решённых задач на выбранный приём пользователь получает доступ к соответствующей части шпаргалки.
6. Пользователь применяет открытую часть шпаргалки в следующих задачах.
7. Для открытия другой части пользователь решает пять задач на другой приём. Прогресс двух приёмов учитывается отдельно.

**До открытия соответствующей части шпаргалки доступно только начальное видео как учебная помощь. Схема изучаемого приёма в шпаргалке ещё недоступна.**

Часть 2×2 открывается после пяти правильно решённых задач на определитель 2×2. Часть 3×3 открывается после пяти правильно решённых задач на определитель 3×3. Просмотр видео сам по себе не открывает учебную схему в шпаргалке.

При неправильном ответе пользователь может повторить попытку и вернуться к видео. Учебная схема остаётся недоступной до выполнения условия награды.

Рядом с текущей задачей пользователь видит счётчик оставшихся задач до следующей награды. При смене урока счётчик показывает прогресс выбранного приёма. Прогресс другого приёма сохраняется.

Пользователь решает на бумаге или в привычном редакторе. Приложение не требует встроенного черновика.

## Визуальное объяснение

Для прототипа допустима управляемая анимация.

Для MVP существующая учебная анимация служит основой. После MVP нужно сравнить несколько вариантов анимации, чтобы пользователь выбрал лучшее направление.

Цель дальнейших экспериментов — собственный узнаваемый стиль, понятная и плавная подача. Ориентир качества — 3Blue1Brown. Окончательный визуальный язык выбирается через несколько проб.

Видео показывает действия по порядку. Для определителя приложение выделяет нужные элементы матрицы, показывает умножение и собирает результат.

Для матрицы 2×2 используются две диагонали. Для матрицы 3×3 используется правило треугольников.

Пользователь выбрал этот образец схемы для 3×3:

https://www.webmath.ru/poleznoe/images/matrix/matricy_pravilo_treugolnika_812.gif

Схема сохраняет расположение элементов внутри матрицы 3×3. Точки, диагонали, треугольники и знаки показывают порядок вычисления.

Видео и соответствующая часть шпаргалки используют одинаковые обозначения. Открытая часть содержит краткую схему из видео.

## Общая шпаргалка и её просмотр

В MVP одна общая шпаргалка с двумя частями: определитель 2×2 и определитель 3×3. Части открываются постепенно. Закрытые части отображаются заглушками со знаком вопроса. После открытия соответствующей части вместо заглушки появляется учебная схема.

Пользователь открывает «Мои шпаргалки». В коллекции MVP предусмотрена одна шпаргалка. Выбор шпаргалки открывает диалоговое окно, где её можно увеличить и рассмотреть подробнее. После закрытия окна пользователь может продолжить решение.

Шпаргалка видна в коллекции с самого начала. До выполнения условий открытия её части закрыты заглушками.

Шпаргалка должна выглядеть как игровая награда. Визуальный ориентир пользователя — коллекционные карточки Hearthstone.

Шпаргалка должна переливаться и анимироваться. Для MVP предусмотрено одно оформление. Улучшения оформления за дальнейшие решения отложены.

Возможные эффекты: переливающаяся поверхность, свечение рамки, частицы и движение при наведении. Сравнение вариантов оформления приложения и шпаргалки отложено до завершения MVP.

Схема на шпаргалке должна оставаться читаемой во время анимации.

Открытие части шпаргалки должно быть заметным событием. Пользователь должен видеть, какой приём он открыл и где его посмотреть.

После пятого правильного решения автоматически открывается диалоговое окно шпаргалки с выделенной новой частью. Пользователь может рассмотреть награду, закрыть окно и продолжить практику. Автоматическое окно появляется только при открытии новой части.

## Будущие награды

Пользователь предложил расширить коллекцию следующими наградами.

| Награда | Идея |
| --- | --- |
| Песня | Пользователь получает песню за достижения и добавляет её в коллекцию. |
| Калькулятор | Пользователь получает инструмент для вычислений как награду. |
| Инженерный калькулятор | Пользователь получает калькулятор с инженерными функциями. |
| Калькулятор матриц | Пользователь получает инструмент для операций с матрицами. |
| Другие инструменты | Коллекция может включать другие полезные инструменты. Конкретный список пока отсутствует. |

Шпаргалки сохраняют изученные приёмы. Песни могут давать отдельный повод собирать коллекцию. Калькуляторы дают пользователю новые возможности.

Условия выдачи песен и калькуляторов пока не определены. Источник песен и способ их воспроизведения тоже не определены.

В следующих версиях вознаграждение должно расти по мере увеличения числа решённых задач. Конкретные награды и условия их получения ещё предстоит определить.

## Согласованный объём MVP

Текущий фокус — два урока: определители 2×2 и 3×3. В коллекции одна общая шпаргалка с двумя постепенно открывающимися частями.

Видимые закрытые части должны давать повод продолжить обучение. Общую шпаргалку можно открыть в диалоговом окне и увеличить для подробного просмотра.

В каждом уроке нужны видео, генерируемые задачи и соответствующая часть общей шпаргалки. После получения награды пользователь может продолжать практику с открытой частью шпаргалки.

В MVP пользователь открывает части шпаргалки. Улучшения её оформления за практику оставлены на следующие версии.

Для коллекции потребуется локальное сохранение наград и прогресса. Конкретный способ хранения нужно выбрать при разработке.

Песни и калькуляторы остаются идеями для следующих версий. Включение этих наград в MVP пользователь пока не согласовал.

## Проверки механики наград

1. До открытия соответствующей части шпаргалки пользователь получает учебную помощь только через видео.
2. Часть 2×2 открывается после пяти правильно решённых задач 2×2. Часть 3×3 открывается после пяти правильно решённых задач 3×3. Прогресс считается отдельно.
3. В «Моих шпаргалках» доступна одна общая шпаргалка с частями 2×2 и 3×3.
4. Выбор шпаргалки открывает диалоговое окно с увеличением для подробного просмотра.
5. После закрытия окна пользователь может продолжить решение.
6. Повторное открытие экрана сохраняет ранее открытые части шпаргалки.
7. После перезапуска приложения пользователь сохраняет полученные награды.
8. Каждая кнопка выполняет действие или явно объясняет условие доступа.
9. До получения награды в коллекции видна общая шпаргалка с закрытыми частями. Заглушки со знаком вопроса заменяются схемами по мере открытия частей.
10. Оба урока доступны с самого начала. Часть 3×3 можно открыть раньше части 2×2.
11. Счётчик показывает число оставшихся правильно решённых задач до следующей награды.
12. После открытия новой части автоматически появляется диалоговое окно с выделенным фрагментом. Следующие правильные ответы на тот же приём не открывают это окно повторно.

## Требования к запуску и исходникам

Установленное приложение должно работать исключительно локально. Интернет и учётная запись для его работы не нужны. Установка и обновление зависимостей могут использовать интернет.

Весь исходный код должен находиться в проекте пользователя. Пользователь должен иметь возможность редактировать код и переносить приложение.

Для работы приложения не нужны Sites, внешние API, CDN и внешние шрифты.

Публикация приложения и выгрузка исходников требуют нового явного указания пользователя.

## Состояние существующего прототипа

Папка `matrix-lab` содержит локальный прототип. Инструкции запуска находятся в `matrix-lab/README.md`.

Прототип пока открывает шпаргалку до первого решения. Это поведение не соответствует принятой механике наград.

Прототип пока хранит прогресс только в памяти вкладки. При обновлении страницы прогресс пропадает.

Полноценные анимированные награды, улучшения шпаргалок, песни и калькуляторы пока отсутствуют.

Существующие проверки навигации допускают получение шпаргалки без решения. При разработке MVP эти проверки нужно изменить.

Ранее прототип разместили в Sites. Пользователь потребовал исключительно локальную работу. Удаление прежней облачной копии не подтверждено. Это отдельная незавершённая задача.

Проверить этот путь на обоих уроках. Проверить доступность схем до и после достижения порога награды.
